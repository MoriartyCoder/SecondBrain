
# Requirements
## Overall

* First and one of the most important phases in the overall model (Requirements analysis, Design, Implementation, Test & Integration, Acceptance & Introduction, Operation & Maintenance)
* **Definition**: Requirements define what properties are expected of a software system
	* A requirement is …
		* a condition or capability required by a user (person or system) to solve a problem or achieve a goal
		* a condition or capability that a system or subsystem must fulfil or possess in order to comply with a contract, standard, specification or other formal document
		* a documented representation of a condition or property according to (1) or (2)
* **Main results**: Document of the requirements specification, concept of user interface (mock up) and analysis model (static and dynamic)
* **Definition of system context**: The origin of all requirements lies in the environment relevant to a software system. Accordingly, it is important to differentiate the system from the environment and identify the parts of the environment that are relevant to the requirements.

## Aim
* What functionality should the software system offer for whom (users!)?
* Which boundary conditions (e.g. hardware/software used) must be met?
* What other properties (e.g. response time behaviour, memory requirements, etc.) are required?

## Actions
* Analysis of the current situation: What is status quo?
* Feasibility analysis: Is it worth it and how much?
* Definition of the system context:
* Determination of requirements: Capabilities of the new system
